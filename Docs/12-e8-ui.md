# 12 — Веб-интерфейс: стиль и компоновка (Э8)

Спецификация внешнего вида и архитектуры страниц `DumaLens.Web`. Функциональные требования к страницам — [04-functionality.md](04-functionality.md) §6, контракт API — §5. Документ фиксирует дизайн-решения Э8; реализация наследует их без расхождений.

## 1. Принципы

- **Data-first.** Продукт — аналитический инструмент по массиву голосований (102 тыс. записей). Приоритет — плотные читаемые таблицы, явные числа, минимум декора. Аудитория: исследователи, журналисты, студенты, граждане.
- **Нейтральный табличный стиль** без тяжёлых зависимостей: один CSS-файл на дизайн-токенах (CSS-переменные), минимум JS. Без Node.js (О-5), без внешних CDN — все стили и скрипты локальные (критерий Э8).
- **Семантика цвета результата** едина во всём интерфейсе: За — зелёный, Против — красный, Воздержался — жёлтый, Не голосовал — серый. Цвет никогда не единственный носитель смысла: рядом всегда текст («ЗА», «ПРОТИВ», «ВОЗД», «НЕ ГОЛ») — для дальтонизма и ч/б печати.
- **Числа:** табличные цифры (`font-variant-numeric: tabular-nums`), выравнивание вправо, единый формат процентов (1–2 знака), явная база процента («от состава» / «от голосовавших»). Нулевые значения в матрицах приглушены серым, не окрашены семантическим цветом.
- **Две темы** (светлая и тёмная) с переключателем; выбор сохраняется. Тёмная тема — приглушённая (не чисто-чёрный фон), комфортная для длительной работы.

## 2. Дизайн-токены

Темы задаются CSS-переменными на `:root` (светлая) и `:root[data-theme="dark"]` (тёмная). Переключение — атрибут `data-theme` на `<html>`; нативным контролам передаётся `color-scheme` (`light`/`dark`).

### 2.3. Типографика и плотность

- Шрифт: `'Segoe UI', system-ui, -apple-system, Helvetica, Arial, sans-serif` (гротеск, без засечек). Заголовки тем же шрифтом.
- Базовый кегль 15px, межстрочный 1.5; заголовки страниц 27px, карточек 21px, секций 18px.
- **Просторная компоновка** (низкая плотность): внутренние отступы карточек `22px 26px`, строк выдачи `18px 22px`, ячеек матрицы `12px 15px`; увеличенные зазоры между блоками.
- **Исключение — список депутатов:** строки плотные (`padding: 5px 13px`), чтобы длинный список (до ~450 человек) оставался компактным.

## 3. Навигация и структура (ИА)

Верхняя навигационная панель (`MainLayout` + `NavMenu`), закреплена при прокрутке:

```
[DL] DumaLens   Поиск · Созывы · Фракции · Депутаты        [Тема] [Войти*]
```

\* Кнопка входа и ролевые разделы появляются на Э9 (`AuthorizeView`); место в панели зарезервировано.

- **Главная `/`** — поиск-герой: крупная строка поиска, сводка массива (голосования, депутаты, фракции, законопроекты, период), быстрые ссылки на созывы, кликабельные примеры запросов (сценарии S1/S2).
- **Хлебные крошки** на карточках: `Главная → Поиск → Голосование № …`.
- **Сквозные ссылки** образуют граф переходов: голосование ↔ законопроект ↔ фракция ↔ депутат ↔ созыв. Ценность продукта — в навигации по связям.
- **Состояние фильтров поиска — в URL** (query-параметры): ссылка воспроизводит запрос, кнопка «Назад» работает (критерий Э8, шаринг).

## 4. Архитектура страниц

Паттерн эталона `DocumentGenerator.Web`, данные — только через `DumaLens.Api.Client` (HTTP к Api), бизнес-логики в Web нет ([05-architecture.md](05-architecture.md) §2.3).

| Слой | Содержимое | Правило |
|---|---|---|
| `Components/Pages/` | routiруемые страницы | композиция + состояние; тонкие |
| `Components/Layout/` | `MainLayout`, `NavMenu`, `Breadcrumbs`, `ThemeToggle` | общий каркас |
| `Components/Shared/` | переиспользуемые презентационные компоненты | параметры на вход, события на выход |

**Каталог общих компонентов:**

- `ResultBadge` — бейдж результата/итога (цвет + текст).
- `FactionStatsTable` — матрица «фракция × За/Против/Воздержался/Не голосовал» с процентами и переключателем базы.
- `DeputyList` — депутаты по фракциям с цветовой индикацией; виртуализация длинных списков (`Virtualize`).
- `VoteRow` — строка выдачи поиска: заголовок, мета, итог, мини-таблица фракций.
- `ConditionBuilder` — конструктор фракционных условий (динамические строки).
- `Pager` — пагинация.
- `StatCard` — карточка-метрика сводки.
- `LoadingBlock`, `EmptyState`, `ErrorBlock` — единые состояния загрузки/пусто/ошибка.

Базовые фильтры поиска свёрстаны в `Search.razor` (отдельный компонент не выделялся); состояние темы — `wwwroot/theme.js` + `localStorage` (без C#-сервиса).

**Паттерн состояния страницы:** URL → запрос через клиент → рендер. Каждая страница владеет своим состоянием. Поиск подписан на `NavigationManager.LocationChanged` (с отпиской в `Dispose`): при смене только query-строки (пагинация, «Найти», сортировка) `OnParametersSetAsync` не срабатывает, поэтому повторный поиск запускает обработчик `LocationChanged` (с защитой от повторной обработки того же URL). Простые страницы — `@code` в `.razor`; тяжёлые (`Search`, `VoteCard`) — code-behind `.razor.cs` (partial class) для читаемости разметки.

**Регистрация клиента:** клиенты NSwag (`IVotesClient`, `IBillsClient`, `IFactionsClient`, `IDeputiesClient`, `IConvocationsClient`, `IStatsClient`) регистрируются в DI напрямую поверх именованного `HttpClient` «DumaLensApi» с базовым адресом из конфигурации `ApiSettings:BaseUrl`. Отдельный слой обёрток не нужен: сгенерированные интерфейсы — уже абстракция для подмены и моков, бизнес-логики в Web нет.

## 5. Конструктор фракционных условий

Динамические строки, объединённые логическим **И** (до 10 условий — ограничение API; кнопка добавления блокируется на лимите). Строка условия:

- **Фракция** — select (канонические фракции из справочника).
- **Результат** — select: За / Против / Воздержался / Не голосовал (`accept`/`decline`/`abstain`/`none`).
- **Оператор** — select: ≥ / ≤ (`gte`/`lte`).
- **Порог** — слайдер 0–100 с предустановками 50 / 66,7 / 90 / 100 и числовым значением.
- **База процента** — переключатель «от состава / от проголосовавших» (`members`/`voted`); для результата «Не голосовал» доступна только «от состава» (§1.2 [04-functionality.md](04-functionality.md)).

Состояние конструктора сериализуется в URL (`factionConditions[i].faction/result/operator/threshold/basis`). Кнопки «Добавить условие», «Сбросить фильтры», удаление строки.

## 6. Формы и контролы

- **Селекты:** `appearance: none` + собственная стрелка-шеврон (inline SVG), скруглённое focus-кольцо через `box-shadow` (не системный `outline`). Единообразно во всех браузерах, без нативных артефактов (квадратная рамка поверх скруглений, перекраска стрелки в тёмной теме). Опции списка — `background: var(--surface); color: var(--text)`.
- **Слайдер порога:** явная стилизация дорожки и ползунка — круглый ползунок цвета акцента с контрастной обводкой (не сливается с фоном), дорожка заполняется акцентом до текущего значения. Работает в обеих темах. Значение `value` рендерится в `InvariantCulture` (иначе десятичная запятая культуры сервера сбрасывает ползунок браузером в середину). Заполнение и текст процента обновляются **во время перетаскивания** клиентским JS (`theme.js`, слушатель `input`) без серверного ре-рендера; фиксация значения в Blazor — по `@onchange` (отпускание). Текст процента — единый текстовый узел (`PercentLabel`), JS мутирует его `nodeValue` (не `textContent`, чтобы не отсоединять узел от diff-дерева Blazor). Пресеты 50/66,7/90/100 синхронно меняют значение, заполнение и текст.
- **Даты:** нативные `input[type=date]` в `color-scheme` темы.
- **Focus:** видимое скруглённое кольцо `box-shadow: 0 0 0 3px color-mix(in srgb, var(--accent) 40%, transparent)` + граница акцента.

## 7. Переключатель тем

- Механизм: CSS-переменные двух тем + атрибут `data-theme` на `<html>`. Переключатель в навигации меняет атрибут.
- Сохранение выбора в `localStorage`; при первом входе — системная тема (`prefers-color-scheme`), по умолчанию светлая.
- Инициализация до первой отрисовки (синхронный скрипт `theme.js` в `<head>`), чтобы избежать «мигания» темой.
- `color-scheme` передаётся нативным контролам (даты, селекты, слайдеры) для корректного рендера в тёмной теме.

## 8. Доступность и UX

- Цвет результата всегда дублируется текстом; нули приглушены, не семантически окрашены.
- Контраст текста ≥ WCAG AA в обеих темах; видимый focus у интерактивных элементов.
- Табличные цифры, выравнивание чисел вправо, явная база процентов.
- Липкие шапки таблиц (внутри контейнера `.table-scroll` с `max-height: 60vh`); горизонтальная прокрутка матриц на узких экранах.
- Виртуализация длинных списков депутатов.
- Единые состояния загрузки/пустого результата/ошибки на всех страницах.
- Адаптивность: фильтры и конструктор перестраиваются в одну/две колонки на узких экранах; навигация переносится второй строкой (пункты прокручиваются горизонтально), а не скрывается.

## 9. Тестирование (Э8)

Интеграционные тесты Web-хоста (`DumaLens.Web.Tests`): рендер всех страниц, передача параметров поиска клиенту (S1: текст + созыв; S2: фракционные условия из URL), устойчивость к некорректным индексам условий и лимиту 10, видимая ошибка при недоступном Api. Сценарии MVP S1–S4 замысла проходят через UI: поиск «алкоголь» → карточка 500091-8 → хронология; конструктор «НЛ ЗА ≥ 70% И КПРФ ПРОТИВ ≥ 50%» → выдача; ссылка с фильтрами воспроизводит запрос. S5–S6 (карточка депутата по темам, теги законопроектов) — v1.1+, вне Э8. UI работает без внешних CDN.
