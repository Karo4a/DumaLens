# 03 — Техническое задание: DumaLens

Версия 1.0 (этап проектирования). Основания: паспорт данных ([02-data-sources.md](02-data-sources.md)), замысел ([01-vision.md](01-vision.md)).

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название | DumaLens — поисковая система и аналитика голосований Госдумы РФ |
| Назначение | Поиск, фильтрация и анализ голосований депутатов ГД РФ по законопроектам, фракциям, депутатам, датам и пользовательским меткам |
| Объект автоматизации | Массив пленарных голосований ГД РФ 1994–2024 (102 320 голосований, ~45,6 млн голосов депутатов) + текущие голосования с сайта `vote.duma.gov.ru` |
| Пользователь | Автор проекта |
| Порядок оформления | Документы в `Docs/`, код в корне репозитория; язык документации и интерфейса — русский |

## 2. Ограничения и технологический стек (обязательные)

| № | Ограничение |
|---|---|
| О-1 | Платформа строго **.NET 8** (целевая среда поддерживает только .NET 8). Целевой фреймворк всех проектов — `net8.0` |
| О-2 | IDE — **Visual Studio 2022**; решение `.sln` должно открываться и собираться в VS 2022 без дополнительных компонентов |
| О-3 | Язык — **C# 12**; стиль кода и архитектура — по проектам **Specular** (приоритетный ориентир) и **DocumentGenerator** (ветка master) (подробно в [05-architecture.md](05-architecture.md)) |
| О-4 | СУБД — **PostgreSQL 16+** (EF Core 8, Npgsql). Отдельный поисковый движок (Meilisearch/OpenSearch) на MVP **не используется** |
| О-5 | Развёртывание — один сервер (Windows или Linux) с **уже развёрнутым PostgreSQL**; два хоста (`DumaLens.Api` и `DumaLens.Web`) на разных портах; без обязательного Docker, Kubernetes, Node.js и внешних облачных сервисов |
| О-6 | Внешние сетевые обращения приложения — только к `vote.duma.gov.ru` (парсер) и NuGet при сборке. Никаких платных API |
| О-7 | Секреты (строки подключения и т.п.) — в конфигурации/переменных окружения, не в репозитории |
| О-8 | Исходные данные архива не изменяются; импорт читает `vote-master.zip` потоково, без обязательной распаковки на диск |

## 5. Требования к данным

- Канонические коды результатов: `accept`, `decline`, `abstain`, `none` (опечатка `declice` из README источника не используется).
- Даты хранятся с часовым поясом (`timestamptz`); смещения исходных данных (+0300/+0400) сохраняются при парсинге, отображение — в московском времени.
- Идентификаторы сайта (голосование, депутат, фракция) — числовые, хранятся как `bigint`; номер законопроекта — строка вида `500091-8`; код созыва — строка `AAAAAAA8`.
- Пустые голосования (78 в архиве) хранятся с признаком `HasResults = false` и исключаются из процентной аналитики.
- Полнота: после импорта архива + обхода сайта в БД присутствуют все голосования I–IX созывов, доступные на сайте; пробелы сайта (id с HTTP 500) фиксируются в журнале.

## 6. Состав работ и порядок сдачи

Этапы и задачи детализированы в [06-implementation-plan.md](06-implementation-plan.md). Порядок: каркас решения → модель данных (+база ролей) → импорт архива → нормализация/агрегаты → поиск → API → парсер живого сайта → UI → аутентификация/роли → производительность и развёртывание. После каждого этапа — ревью кода и прогон тестов; этап считается принятым при выполнении его критериев приёмки.

## 7. Критерии приёмки MVP (сводный чек-лист)

| № | Критерий | Метод проверки |
|---|---|---|
| П-1 | `verify`: 102 320 голосований, 45 593 720 голосов депутатов, суммы по созывам и кодам результатов совпадают с паспортом | CLI `verify`, отчёт |

## 8. Глоссарий

| Термин | Определение |
|---|---|
| Голосование (vote) | Одно пленарное голосование по одному вопросу; единица поиска |
| Законопроект (bill) | Сущность с номером вида `500091-8`; объединяет голосования по стадиям |
| Стадия | Нормализованный этап рассмотрения: первое/второе/третье чтение, принятые/отклонённые поправки, «за основу», «в целом», процедурное |
| Позиция фракции | Вычисляемая характеристика: доля голосов определённого результата в фракции относительно выбранной базы, сравниваемая с порогом |
| База расчёта | `members` — все депутаты фракции в данном голосовании; `voted` — только голосовавшие (За+Против+Воздержался) |
| Каноническая фракция | Логическая фракция (ЕР, КПРФ, …) с историческими периодами (site-id, название, созыв) |
| Созыв | Период работы ГД (I–IX); код сайта `AAAAAAA1…9` |
| Карантин | Журнал аномальных записей импорта, не попадающих в выдачу |
| Роль | Уровень доступа: Пользователь / Модератор / Администратор (иерархия прав); одна роль на пользователя |
| Аутентификация / авторизация | Проверка личности (логин/пароль → JWT access + refresh) / проверка прав роли на эндпоинт |
