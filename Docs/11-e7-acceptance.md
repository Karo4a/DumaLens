### Корневая причина медленного обхода: session-cookie WAF (главный урок Э7)

Симптом: parallel=8 давал лишь ~4 req/s (пачка 100 карточек ~26 с), при этом python
с той же машины — 26 req/s; процесс кроулера в это время 0% CPU (чистое ожидание сети).
Перебраны и отвергнуты гипотезы: прокси/WPAD (UseProxy=false — без эффекта), Nagle
(NoDelay — без эффекта, raw-сокеты быстры в обоих режимах), keep-alive vs close
(ConnectionClose — без эффекта), brotli (исключён — без эффекта), пул соединений
(netstat: 18 ESTABLISHED, конкурентность есть). Решающий эксперимент — raw-сокеты
с cookie и без: **без cookie 24,4 req/s, с cookie `session=…` 4,3 req/s** (последовательно
с cookie — 0,3 с/запрос: WAF ограничивает именно одновременные запросы одной сессии).
Сайт выдаёт Set-Cookie session на первый ответ; HttpClient по умолчанию принимает
cookie (UseCookies=true) и возвращает на всех последующих запросах → throttling.
Исправление: **UseCookies=false** (+ UseProxy=false, gzip) в фабрике HttpClient —
коммит ce44998; регресс: фикстура выдаёт session-cookie, тест проверяет, что кроулер
не отправляет Cookie. Эффект: IX 437 карточек за 28 с вместо ~10 мин.

### Исправление: утверждение о смене разметки сайта было ошибочным

Сайт **не менял** разметку. Все фикстуры Э2 (vote_126282, vote_17470, vote_procedural)
имеют ту же структуру, что и живые карточки: var-список «var chart, deputiesData, …;»,
затем присваивание «deputiesData = […]»; JSON с полями letter/name. Regex парсера
без обязательного var корректен с Э2. Ошибка: при анализе парсера ожидался regex
с обязательным `var\s+`, и несоответствие живого HTML этому ложному ожиданию было
ошибочно объяснено «миграцией шаблона»; на этом ложном основании обход был остановлен
(целостность не пострадала: 4200 карточек, 0 сирот/дублей). Сверка с committed-кодом
(git show HEAD:file) и байтами фикстур подтвердила: внешних изменений не было.
Регресс-фикстур живой карточки 135715 оставлен под именем vote_135715.html,
тест Parse_LiveCard135715_ExtractsAllFields (Parsing.Tests 152).

## Известные ограничения (не дефекты)

- **HTTPS сайта может быть недоступен в отдельных сетях** (TCP 443 timeout; порт 80 работает).
  В таком случае обход выполняется по `--base-url http://vote.duma.gov.ru`. Карточки и листинги
  отдают полноценный контент по HTTP (проверено).
- Дрейф листингов во время обхода: новые голосования добавляются в начало (страница 1),
  сдвигая элементы к непосещённым страницам — пропуски не возникают, повторы гасятся
  HashSet очереди и обновлением карты существующих; расхождение счётчика «из N» с собранным
  логируется. Удаления голосований сайтом (редкость) могли бы дать пропуск — контроль счётчиком.
- `--from-page` возобновляет только листинги; добор Outcome страниц ранее начальной
  не выполняется (полный повтор без --from-page добирает всё).
- Карантин сайта хранит сырой HTML в `RawJson` (имя колонки историческое, Э3); причина —
  коды валидатора Э2 + «код созыва не соответствует листингу» + повторяющиеся депутаты.
- Фикстуры листингов Э2 имеют исторические имена (listing_ix_p1.html содержит 16 689/835 —
  полный листинг VIII на момент снятия); тесты проверяют содержимое файлов, имена не менялись.
