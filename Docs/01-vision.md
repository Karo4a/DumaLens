# 01 — Замысел и цели DumaLens

## 1. Проблема

Государственная Дума публикует результаты всех пленарных голосований на сайте `vote.duma.gov.ru`, но сайт даёт только линейный просмотр: список голосований по датам и карточку одного голосования. Ответить на аналитические вопросы по массиву голосований штатными средствами нельзя:

- В каких голосованиях фракция голосовала консолидированно «ЗА», а в каких раскалывалась?
- Где позиции двух фракций расходились (одна «ЗА», другая «ПРОТИВ»)?
- Как фракция голосовала по конкретному законопроекту на всех стадиях (чтения, поправки)?
- Какие законопроекты несут наибольшую общественную значимость и как они размечены по тематике?

Массив данных большой: **102 320 голосований за 1994–2024 годы, ~45,6 млн индивидуальных голосов депутатов** (проверено по архиву). Нужна система, которая загружает эти данные, нормализует их и даёт быстрый поиск и аналитику.

## 2. Замысел

DumaLens — поисковая система / веб-приложение для анализа законопроектов и голосований Госдумы РФ:

1. **Хранилище** всех голосований с историей с 1994 года, пополняемое с живого сайта.
2. **Мощный поиск и фильтрация**: по тексту, номеру законопроекта, стадии, дате, созыву, фракциям, депутатам, тегам и рейтингу важности.
3. **Фракционная аналитика** — ядро системы: позиция фракции в голосовании вычисляется с настраиваемым порогом («что считать голосом ЗА») и настраиваемой базой процента (от состава фракции / от проголосовавших). Поддерживаются произвольные комбинации условий по нескольким фракциям, включая поиск расхождений.
4. **Метки (теги)** законопроектов и голосований: тематические («Укрепление законодательного статуса регионов в зоне действия СВО») и оценочные («Репрессивная поправка», «Увеличение штрафа»), положительные и отрицательные. Ручная разметка + автоматические правила по ключевым словам с модерацией.
5. **Оценка важности** законопроектов и поправок для народа: экспертная оценка, пользовательские оценки, итоговый рейтинг (в перспективе — байесовский).
6. **Роли и доступ** (база): Пользователь / Модератор / Администратор, аутентификация и авторизация — фундамент для модерации тегов и пользовательских оценок.

## 4. Границы

### Входит в MVP (v1.0)

- Импорт полного архива голосований (1994–2024) и инкрементальное обновление с живого сайта (включая IX созыв, начавшийся 30.09.2026).
- Нормализация: депутаты, фракции (с историей названий), созывы, законопроекты (номер + стадия из заголовка), агрегаты по фракциям.
- Поиск: полнотекстовый по заголовкам, фильтры (созыв, период, стадия, номер законопроекта, фракционные условия с порогами).
- Карточки: голосование (результаты по фракциям и депутатам), законопроект (хронология голосований), фракция, депутат (базовая).
- REST API (`DumaLens.Api`) + Swagger, веб-интерфейс поиска и карточек (`DumaLens.Web`, Blazor Server).
- База ролей и аутентификации: Пользователь / Модератор / Администратор, JWT + refresh (включается на Э9; спецификация — [07-security.md](07-security.md)).

### Отложено (после MVP)

- Теги и правила автотегирования с модерацией (v1.1).
- Рейтинги важности: экспертные и пользовательские оценки (v1.2; опираются на базу аутентификации из MVP).
- Аналитические дашборды, сравнение депутатов, экспорт выборок (v1.2+).
- ML-тегирование, рекомендательная система, публичный API с ключами (v2+).
- Мобильные приложения, многоязычность.

### Не входит никогда (сознательные исключения)

- Тексты законопроектов и пояснительные записки с СОЗД (`sozd.duma.gov.ru`) — отдельный источник со своей моделью; в MVP связь с законопроектом только по номеру. Возможен переход по ссылке на СОЗД без парсинга.
- Данные о комитетах, авторах законопроектов, стенограммы заседаний.
- Юридические заключения и прогнозы исхода голосований.

## 5. Критерии успеха MVP

1. Полный архив импортирован без потерь: 102 320 голосований, контрольные суммы по созывам совпадают с паспортом данных ([02-data-sources.md](02-data-sources.md)).
2. Запрос S2 («НЛ ЗА ≥ 70%, КПРФ ПРОТИВ ≥ 50%») выполняется по всему массиву и возвращает корректный результат (проверяется на эталонных голосованиях, посчитанных вручную).
3. Поиск и фильтрация по 100 тыс. голосований отвечают быстрее 1 секунды (p95) на типовой машине.
4. Данные актуальны: парсер догоняет живой сайт до текущего дня, повторные запуски идемпотентны.
5. Проект собирается в Visual Studio 2022 на .NET 8 и проходит ревью кода без блокирующих замечаний.
