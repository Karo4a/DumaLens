## 3. Планы запросов (EXPLAIN ANALYZE, BUFFERS)

- **FTS, count**: `Bitmap Index Scan` по GIN-индексу `IX_Vote_TitleSearch` — 2,9 мс на 530 совпадений.
- **FTS, страница (dateDesc, LIMIT 20)**: `Index Scan Backward` по `IX_Vote_VotedAt` + фильтр
  `TitleSearch @@ 'алкогол':*` + `Incremental Sort` — 3,6 мс (планировщик выбирает порядок по дате
  с ранним остановом на LIMIT, а не полное сканирование GIN-индекса).
- **Фракционное условие (НЛ ЗА ≥ 70%, LIMIT 20)**: `Nested Loop Semi Join` (EXISTS) +
  `PK_VoteFactionStats` — 0,8 мс.
- **П-3 (два EXISTS, LIMIT 20)**: `Bitmap Index Scan` по `IX_VoteFactionStats_FactionId_DeclinePctMembers`
  (индекс Э4: КПРФ ПРОТИВ ≥ 50 → 7 478 кандидатов) → `PK_Votes` → semi-join по НЛ ЗА ≥ 70 → 223 строки →
  top-N heapsort. Холодный прогон 377 мс (14 898 буферов с диска), прогретый ≈ 124 мс.
- **Даты**: `Index Scan Backward` по `IX_Vote_VotedAt` + построчный фильтр
  `VotedAt + make_interval(UtcOffsetMinutes)` в границах московских дат (отфильтровано 32 289 строк) — 38 мс.
  Фильтр non-sargable (смещение per-row); кандидат на оптимизацию — выраженный индекс. Для MVP не требуется:
  НФТ-01 выполняется с запасом, худший дата-запрос 231 мс.

## 4. П-3 — независимая сверка

Запрос: **НЛ ЗА ≥ 70% от списочного состава И КПРФ ПРОТИВ ≥ 50% от списочного состава**.

- Сервис (полная пагинация по 100): **223 голосования**.
- Независимый SQL: проценты пересчитаны из сырых `DeputyVotes` (45,6 млн строк) через
  `FactionPeriods`/`Factions` с `ROUND(..., 2)` — **множества идентификаторов совпали полностью**
  (223 = 223, расхождений 0; сверка повторена на финальном коде).
- Три эталонных голосования (начало/середина/конец набора по дате): **115629** (14.10.2021),
  **120151** (06.12.2022), **126236** (28.02.2024). Сверка всех счётчиков и процентов по каждой фракции:
  **234 значения, 0 расхождений** (6 счётчиков + 7 процентов на фракцию).
- Пример — 115629 (первое чтение, законопроект 1201518-7):
  НЛ 14/15 = **93,33% ЗА**; КПРФ 46/57 = **80,70% ПРОТИВ**; ЕР 298/326 = 91,41% ЗА.
  Для 126236: КПРФ 52/57 = 91,23% ПРОТИВ при 3 ЗА (5,26%) — порог по «против» работает независимо от «за».
- Округление: SQL `ROUND` ≡ C# `MidpointRounding.AwayFromZero` (подтверждено на Э4).

## 5. П-4 и выбор FTS-парсера

- Поиск «алкоголь» находит **530 голосований, включая все 4 голосования законопроекта 500091-8**;
  фильтр по номеру возвращает ровно 4 (интеграционный сценарий §3.4 №3 — номер + третье чтение).
- **`websearch_to_tsquery` отклонён по факту замера на архиве**: конфигурация `russian` не связывает
  прилагательное и существительное («алкогольной» → `алкогольн`, «алкоголя» → `алкогол`), поэтому
  `websearch_to_tsquery('russian', 'алкоголь')` давал **2 совпадения против 530** и не находил 500091-8 —
  нарушение П-4.
- Реализован `RussianTsQueryBuilder` (`DumaLens.Repositories/Search`): `to_tsquery('russian', …)`
  с **префиксными лексемами** `слово:*` (`алкоголь:*` → `'алкогол':*` покрывает обе формы).
  Синтаксис: пробел = И, `"фраза"` = соседство (`<->`), `-слово` = НЕ, `OR`/`|` = ИЛИ.
  Морфологию выполняет PostgreSQL; построитель только расставляет операторы и очищает ввод.
- Устойчивость построителя проверена на живом PostgreSQL: лексемы только из `[\p{L}\p{N}-]`,
  служебные символы tsquery недостижимы; краевые случаи (ведущие/повторные/хвостовые дефисы,
  стоп-слова, фразы, отрицание, номера законопроектов, нелатинские буквы) — синтаксических ошибок нет.
- Выбор зафиксирован в [04-functionality.md](04-functionality.md) §3.1.

## 6. Особенности данных (не дефекты поиска)

- **Исход голосования во всём архиве — `Unknown`** (102 309 из 102 309): архив не содержит поля исхода
  (Э3). Фильтр `outcome=accepted/rejected` проверен синтетическими тестами; на архиве комбинация
  стадия+исход возвращает только `Unknown` — это свойство данных.
- 78 пустых голосований хранятся с `HasResults=false` (Э3); при фракционных условиях поиск по умолчанию
  ограничивается голосованиями с результатами (`HasResults=true`).
- Даты — московское время с историческим смещением (`UtcOffsetMinutes`, +03/+04); границы фильтра
  включительные, сравнение идёт по московской дате голосования (интеграционный тест на смещении +04:00).
