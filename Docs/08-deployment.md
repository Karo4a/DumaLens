# 08 — Разворачивание без прав администратора (Windows)

Сценарий: разовый импорт архива голосований + демонстрация проекта на машине без прав
администратора Windows. Админ-права не требуются ни на одном шаге.

## Исходные условия

| Компонент | Состояние |
|---|---|
| PostgreSQL | Уже установлен; вход под учёткой `postgres` (суперпользователь) |
| .NET | SDK/runtime 8 уже установлен |
| Visual Studio | Не обязательна (всё делается из cmd); для работы в IDE — VS 2022 17.8+, см. раздел ниже |
| Интернет | Есть, NuGet-restore возможен |
| Железо | 4–6 ядер, 16 ГБ ОЗУ, SSD (возможно замедление антивирусом) |
| Сценарий | Разовый импорт + демонстрация |

## Что требует прав и что делать без них

| Действие | Нужны права? | Решение без админа |
|---|---|---|
| Установка PostgreSQL | Админ Windows | Не требуется — сервер уже установлен |
| Правка `postgresql.conf`, рестарт службы | Админ Windows | Не требуется — весь тюнинг сеансовый (`SET ...`), выполняется автоматически |
| Создание базы `dumalens` | Суперпользователь PG | Есть (`postgres`); базу создаёт сам импортёр (`MigrateAsync`) |
| Удаление/создание индексов и FK (bulk) | Владение таблицами PG | Есть (`postgres` — суперпользователь) |
| Отключение FK-триггеров | Суперпользователь PG | Есть; при его отсутствии — автоматический пропуск с предупреждением |
| Сборка / запуск .NET | Не нужны | SDK установлен; либо привезти готовые бинарники Release |
| Исключения антивируса | Админ Windows | Недоступны — компенсируются bulk-режимом (минимум дискового I/O) |

**Матрица деградации оптимизаций** (если учётка `postgres` окажется ограниченной):

| Режим | Требование | Поведение при нехватке прав |
|---|---|---|
| `--bulk` | Владение `DeputyVotes`/`VoteFactionStats` | Предупреждение в лог, импорт в обычном режиме |
| Отключение FK-триггеров | Суперпользователь PG | Предупреждение в лог, импорт с триггерами |
| `--workers`, `--batch`, `--max-files` | Ничего | Всегда доступны |

Импорт завершится корректно при любых правах — разница только в скорости.
Ничего перенастраивать вручную не нужно.

## Работа в Visual Studio (не обязательна для разворачивания)

Импорт и демонстрация выполняются из cmd и Visual Studio не требуют. Если решение
открывается в IDE, версия VS должна поддерживать .NET 8: **Visual Studio 2022 17.8+**
(MSBuild не ниже 17.8.3), рекомендуется актуальная 17.x.

Симптом старой VS (например, 17.4): «Не удается открыть файл проекта. Для пакета SDK
для .NET версии 8.0.4xx требуется версия MSBuild не ниже 17.8.3. Текущая версия
MSBuild — 17.4.x» — проекты не загружаются. Причина: MSBuild внутри VS старее, чем
требует SDK .NET 8; ни один SDK 8.0.x не работает в VS ниже 17.8.

Лечение — **обновить Visual Studio** через Visual Studio Installer (нужны права
администратора Windows). Менять `global.json` не нужно; понижение версии SDK вредно:

- SDK 7.x и ниже не поддерживает `net8.0` — все проекты выгрузятся;
- `rollForward: latestFeature` выбирает старшую установленную ветку 8.0.x, поэтому
  установка SDK 8.0.1xx рядом с 8.0.4xx выбор не меняет.

Консольная сборка (`dotnet build`, скрипты `Deploy\`) от версии VS не зависит:
SDK содержит собственный MSBuild (для ветки 8.0.4xx — 17.11), поэтому `dotnet` из cmd
собирает и запускает проект даже там, где старая VS не открывает решение.

## Подготовка комплекта

1. Скопировать на целевую машину:
   - репозиторий DumaLens (git clone / bundle / zip working tree, без `bin/obj` — либо с готовыми бинарниками Release);
   - `vote-master.zip` (~851 МБ) в корень репозитория.
2. Опционально собрать заранее: `dotnet build -c Release` — на медленной машине
   сборка 29 проектов под антивирусом может занять заметное время. Скрипты при
   каждом запуске выполняют инкрементальную сборку Release (без изменений в коде —
   быстрый проход), поэтому всегда запускается актуальная версия.
3. Пароль учётки `postgres` хранить отдельно (в репозиторий не попадает).

## Разворачивание

1. Разместить комплект **на локальном SSD** машины, например `C:\Users\<user>\DumaLens`.
   Не работать с флешки: антивирус + USB дают худший I/O, а импорт упирается в диск.
2. Задать строку подключения в сеансе cmd (пароль — фактический):
   ```bat
   set ConnectionStrings__DefaultConnection=Host=localhost;Port=5432;Database=dumalens;Username=postgres;Password=***
   ```
   Если сервер на другом хосте/порту — поправить `Host`/`Port`.
3. Запустить импорт:
   ```bat
   Deploy\import.cmd
   ```
   Скрипт: инкрементальная сборка → `import-archive --bulk` → `verify`.
   База `dumalens` создаётся и мигрируется автоматически, отдельный psql/dotnet-ef не нужен.
4. Запустить демонстрацию:
   ```bat
   Deploy\demo.cmd
   ```
   Api: `http://localhost:5200/swagger` (среда Development включается скриптом),
   Web: `http://localhost:5100` (Blazor-интерфейс: поиск, конструктор фракционных условий, карточки).
   После готовности хостов скрипт сам открывает браузер (Swagger и Web, Web — активная вкладка).
   Остановка — закрыть окна `DumaLens.Api` и `DumaLens.Web`.

**Важно:** во время импорта Api должен быть остановлен — отключение FK-триггеров
действует на все сеансы сервера (целостность в этот момент гарантирует импортёр).
В обычном режиме (без `--bulk`) импорт и поиск работают параллельно — пакетные
транзакции не блокируют читателей (НФТ-11, проверено на Э10).

## Публикация хостов (развёртывание без SDK)

Для постоянной эксплуатации хосты публикуются: на целевой машине нужен только
**.NET 8 Runtime (ASP.NET Core Runtime)**, SDK и исходники не требуются (НФТ-08).

1. Публикация на машине с SDK (из корня репозитория):
   ```bat
   dotnet publish DumaLens.Api -c Release -o publish\Api
   dotnet publish DumaLens.Web -c Release -o publish\Web
   ```
   Публикация framework-dependent (RID не задаётся) — папки переносимы между
   Windows/Linux с установленным Runtime 8. В Visual Studio 2022 то же самое
   делается через «Опубликовать» (профиль папки).
2. Скопировать `publish\Api` и `publish\Web` на целевую машину. Строка подключения
   и ключ JWT задаются переменными окружения (в файлы не попадают, О-7):
   ```bat
   set ConnectionStrings__DefaultConnection=Host=localhost;Port=5432;Database=dumalens;Username=postgres;Password=***
   set ASPNETCORE_ENVIRONMENT=Production
   set Auth__SigningKey=<base64-ключ, генерация ниже>
   ```
3. Запуск двух хостов на разных портах (в отдельных окнах/службах):
   ```bat
   dotnet publish\Api\DumaLens.Api.dll --urls http://localhost:5200
   dotnet publish\Web\DumaLens.Web.dll --urls http://localhost:5100
   ```
   Если Api на другом хосте/порту — задать Web `ApiSettings__BaseUrl`
   (например `set ApiSettings__BaseUrl=http://api-host:5200/`), а Api —
   `Cors__AllowedOrigins__0=<origin Web>` для браузерных запросов.
4. Миграции применяют CLI-команды импортёра (`import-archive`, `crawl`,
   `recalc-stats`, `create-admin`) — сами хосты схему не мигрируют. Первичное
   наполнение: `import-archive --bulk` (см. выше) либо перенос уже наполненной базы.

Отличия среды Production от Development: у Api нет Swagger UI и отказ запуска
без `Auth__SigningKey`; у Web — страница `/Error` вместо детальных ошибок и HSTS
(при https-эндпоинте). Ключ подписи и параметры секции `Auth` — ниже и в
[13-e9-auth.md](13-e9-auth.md).

Проверено на Э10: оба опубликованных хоста стартуют на машине с Runtime 8,
поиск и карточки работают через опубликованный Web (отчёт приёмки Э10).

## Периодический кроулер (планировщик)

Сайт обновляется ежедневно; актуальность поддерживает регулярный `crawl`.
Команда идемпотентна: добирает только недостающие голосования и итоги,
остановка безопасна в любой момент. Миграции применяются автоматически.

**Windows (Планировщик заданий, без прав администратора):**

1. Задать строку подключения в пользовательские переменные окружения (один раз):
   ```bat
   setx ConnectionStrings__DefaultConnection "Host=localhost;Port=5432;Database=dumalens;Username=postgres;Password=***"
   ```
   (`setx` без `/M` не требует админ-прав; значение хранится в реестре пользователя
   и доступно задачам планировщика того же пользователя).
2. Создать задачу: «Планировщик заданий» → «Создать простую задачу» → ежедневно
   в ночное время (например 04:00). Действие — запуск программы:
   - Программа: `C:\Program Files\dotnet\dotnet.exe`
   - Аргументы: `E:\DumaLens\DumaLens.Importer\bin\Release\net8.0\DumaLens.Importer.dll crawl --convocation 0 --delay-ms 500 --log E:\DumaLens\crawl.log`
   - Рабочая папка: `E:\DumaLens` (пути заменить на фактические).

   Либо из cmd (эквивалент):
   ```bat
   schtasks /Create /TN "DumaLens Crawl" /SC DAILY /ST 04:00 /TR "\"C:\Program Files\dotnet\dotnet.exe\" E:\DumaLens\DumaLens.Importer\bin\Release\net8.0\DumaLens.Importer.dll crawl --convocation 0 --delay-ms 500 --log E:\DumaLens\crawl.log"
   ```
3. Вежливые настройки по умолчанию (`--parallel 1 --delay-ms 1000`) консервативны;
   `--delay-ms 500` — пауза 0,5 с между запросами (требование ФТ-06).
   Замеренная рабочая точка `--parallel 8 --delay-ms 0` допустима для разового
   догона (сайт выдерживает), для регулярных задач рекомендуется пауза ≥ 0,5 с.

Длительность: обход листингов всех созывов — ~5500 страниц; при `--delay-ms 500`
это ~1 час, новые карточки добавляются минутами. Полный обход I–IX в рабочей
точке занял 33 мин (замер на тестовой машине, 18.11.2026).

**Linux (cron):**
```cron
0 4 * * * cd /opt/dumalens && ConnectionStrings__DefaultConnection="..." /usr/bin/dotnet DumaLens.Importer/bin/Release/net8.0/DumaLens.Importer.dll crawl --convocation 0 --delay-ms 500 --log /var/log/dumalens/crawl.log
```

## Аутентификация: ключ JWT и первый администратор (Э9)

1. Ключ подписи JWT — случайные 32 байта, base64. Сгенерировать один раз (PowerShell):
   ```powershell
   $rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
   $bytes = New-Object byte[] 32
   $rng.GetBytes($bytes)
   [Convert]::ToBase64String($bytes)
   ```
   Задать в сеансе cmd перед запуском Api (в репозиторий не попадает, О-7):
   ```bat
   set Auth__SigningKey=<сгенерированный base64>
   ```
   Без ключа Api в среде Development запускается с временным ключом на время жизни
   процесса (предупреждение в журнале; сессии не переживают перезапуск) — для демо
   этого достаточно. В Production отсутствие ключа — отказ запуска. Ключ и диапазоны
   настроек валидируются при старте (`AuthOptions.Validate`): не-base64 или короче 32 байт —
   отказ запуска с понятной ошибкой. Остальные параметры
   секции `Auth` (сроки токенов, итерации PBKDF2, блокировка попыток, rate limit,
   grace-окно обновления, очистка токенов) —
   [13-e9-auth.md](13-e9-auth.md), значения по умолчанию подходят для развёртывания.
   Очистка утративших силу refresh-токенов выполняется фоновой службой Api автоматически
   (раз в сутки, хранение 7 дней) — отдельного планировщика не требует.
2. Создать первого администратора (временный пароль печатается один раз; смена
   обязательна при первом входе):
   ```bat
   dotnet run --project DumaLens.Importer -c Release -- create-admin --login admin --name "Администратор"
   ```
   Команда сама накатывает миграции. Вход — кнопка «Войти» в Web-интерфейсе;
   управление пользователями — раздел «Пользователи» (роль Administrator).

## Переход существующей базы на int-ключи (ADR-14)

Новые развёртывания ничего не требуют: схема сразу создаётся с int-ключами.
Базы, наполненные **до** перехода, переводятся одноразовым скриптом:

```bat
set ConnectionStrings__DefaultConnection=Host=localhost;Port=5432;Database=dumalens;Username=postgres;Password=***
Deploy\transition-int-keys.cmd
```

Скрипт спрашивает подтверждение (показывает имя целевой базы; `--yes` — без вопроса),
затем: `recalc-stats` (применяет миграцию `IntKeysDeputyVotes` — `DeputyVotes`
пересоздаётся пустой с узкими ключами, агрегаты очищаются) → `import-archive --bulk`
(полный реимпорт, ~6 мин на эталоне) → `verify` (24/24). Api и Web на время перехода
остановить. SDK/dotnet-ef/psql не нужны — миграцию применяет импортёр.

**Откат** (проверен на живой базе 16.11.2026):

1. `dotnet ef database update 20261115135332_DropVoteFactionStatsNonePctVoted --project DumaLens.Context`
   (Down-миграция возвращает GUID-схему; нужен SDK и `dotnet tool restore`).
2. `TRUNCATE "DeputyVotes", "VoteFactionStats"` (psql).
3. Если в базе есть голосования живого сайта (Э7, `Source = 'Site'`) — удалить их:
   Down-миграция удаляет их индивидуальные голоса, реимпорт архива их не восстанавливает,
   а кроулер пропускает существующие SiteId и не докачает их. Без очистки verify кода
   pre-int-keys (без фильтра Source) не сойдётся с паспортом архива.
   `DELETE FROM "Votes" WHERE "Source" = 'Site'; DELETE FROM "ImportQuarantine" WHERE "SourceUrl" IS NOT NULL;` (psql).
   Колонка `Source` хранит строковые токены (`'Archive'`/`'Site'`), не числа.
4. Полный `import-archive --zip vote-master.zip --bulk` **кодом до перехода** — тег
   `pre-int-keys` (отдельный worktree: `git worktree add ..\dumalens-pre pre-int-keys`).
5. `verify` — 24/24.

## Тюнинг под слабую машину (всё конфигурируемо, права не нужны)

- **Воркеры разбора**: по умолчанию `ядра − 2` (на 4–6 ядрах это 2–4 — уже консервативно).
  Явно: `Deploy\import.cmd --workers 2`.
- **Размер пачки**: по умолчанию 500 голосований на транзакцию. При нехватке ОЗУ:
  `--batch 200`–`300`.
- **GC**: Server GC включён в csproj импортёра; 16 ГБ достаточно. Если память зажата
  другими приложениями: `set DOTNET_gcServer=0` перед запуском (workstation GC).
- **Буфер сборки индексов**: `SET maintenance_work_mem = '256MB'` выполняется
  автоматически на сеанс перед пересозданием индексов — прав администратора не требует.
- **Антивирус**: исключения добавить нельзя, но bulk-режим убирает главный источник
  I/O — обслуживание индексов и FK-триггеров во время COPY. Это основной рычаг.
- **Пробный замер перед полным прогоном**:
  ```bat
  dotnet DumaLens.Importer\bin\Release\net8.0\DumaLens.Importer.dll import-archive --zip vote-master.zip --bulk --max-files 2000 --log probe.log
  ```
  По скорости пробного прогона extrapolируется полное время (102 320 файлов).
  Пробный прогон оставлять в базе нельзя — перед полным импортом пересоздать базу
  (или использовать отдельную одноразовую базу в строке подключения).

## Сбои и восстановление

| Ситуация | Действие |
|---|---|
| Импорт упал после загрузки данных (индексы/FK не пересозданы) | `dotnet DumaLens.Importer\bin\Release\net8.0\DumaLens.Importer.dll restore-schema` — довосстанавливает схему без реимпорта |
| Повторный запуск после аварии | `import-archive` сам довосстанавливает недостающие объекты схемы перед импортом |
| `--bulk` на непустых таблицах | Явная ошибка; использовать обычный режим (при необходимости `--resume`) |
| `verify` не сошёлся | Не демонстрировать; разобрать расхождения по выводу verify |
| Долгие DDL | Таймаут команд схемы — 30 мин (дефолтные 30 с Npgsql убиты); на слабой машине пересоздание индексов 45 млн строк может занять минуты |

```
DumaLens\                 — репозиторий (исходники + при желании бинарники Release)
  vote-master.zip         — архив голосований (~851 МБ)
  Deploy\import.cmd       — инкрементальная сборка + импорт --bulk + verify
  Deploy\demo.cmd         — запуск Api (Swagger) + Web + открытие браузера
  publish\Api\            — опубликованный Api (опционально, для машины без SDK)
  publish\Web\            — опубликованный Web (опционально, для машины без SDK)
```
